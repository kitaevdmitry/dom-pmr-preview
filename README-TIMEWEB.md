# «Династия» — пакет для Timeweb Cloud

Это полная версия сайта: публичный каталог, фильтры, карта, карточки объектов,
заявки собственников и закрытая админ-панель. Администратор может добавлять и
редактировать объекты, загружать фотографии, менять статус публикации,
подтверждать актуальность и обрабатывать заявки.

## Что находится в пакете

- сайт на Next.js;
- PostgreSQL для объектов и заявок;
- контейнерное хранилище PostgreSQL и фотографий для MVP;
- вход администратора по паролю;
- Dockerfile и Docker Compose для Timeweb App Platform;
- автоматическое создание таблиц при первом запуске.

## Публикация в Timeweb Cloud

1. Распакуйте архив и загрузите все файлы в отдельный GitHub, GitLab, GitFlic
   или GitVerse репозиторий. Файл `.env` в репозиторий не добавляйте.
2. В Timeweb Cloud откройте **App Platform → Создать**.
3. Подключите репозиторий и выберите тип **Docker Compose**.
4. Файл конфигурации находится в корне: `docker-compose.yml`.
5. В разделе переменных создайте значения из таблицы ниже.
6. Запустите деплой. После запуска Timeweb покажет технический домен с SSL.
7. Замените `SITE_URL` на полученный адрес, например
   `https://example-app.twc1.net`, и повторите деплой.

## Обязательные переменные

| Переменная | Значение |
|---|---|
| `POSTGRES_PASSWORD` | Случайный пароль базы, минимум 24 символа |
| `ADMIN_PASSWORD` | Ваш отдельный пароль админки, минимум 10 символов |
| `ADMIN_SESSION_SECRET` | Случайная строка, минимум 32 символа |
| `ADMIN_NAME` | Имя, отображаемое внутри админки |
| `ADMIN_EMAIL` | Почта владельца |
| `SITE_URL` | Адрес сайта, который выдаст Timeweb |

Для двух случайных секретов можно использовать менеджер паролей. Не отправляйте
пароли посторонним и не сохраняйте их в Git-репозитории.

## Вход администратора

После публикации откройте:

`https://АДРЕС-САЙТА/admin`

Введите значение `ADMIN_PASSWORD`. Ссылка на админку намеренно не показывается
обычным посетителям. Сессия действует 12 часов, затем потребуется войти снова.

## Проверка после публикации

1. Откройте главную страницу с телефона.
2. Отправьте тестовую заявку из блока продажи недвижимости.
3. Войдите в `/admin` и убедитесь, что заявка появилась.
4. Добавьте тестовый объект, загрузите 2–3 фотографии и выберите точку на карте.
5. Установите статус «Опубликован» и проверьте объект в каталоге.
6. Перезапустите приложение и убедитесь, что объект и фотографии сохранились.

Служебная проверка доступна по адресу `/api/health`; нормальный ответ —
`{"status":"ok"}`.

## Локальный тест

1. Скопируйте `.env.example` в `.env` и замените тестовые значения.
2. Запустите `docker compose up --build`.
3. Откройте `http://localhost:8080` и `http://localhost:8080/admin`.

## Важно о сохранности данных MVP

Timeweb App Platform запрещает директиву `volumes` в `docker-compose.yml`,
поэтому этот пакет использует внутреннее контейнерное хранилище PostgreSQL и
объявленное в Dockerfile хранилище фотографий. Данные переживают обычный
перезапуск контейнера, однако перед удалением приложения, пересозданием сервера
или крупным обновлением необходимо сделать резервную копию.

На этапе публичного запуска базу следует перенести в управляемый PostgreSQL, а
фотографии — в S3. Для командного MVP текущая конфигурация позволяет проверить
админку и весь пользовательский сценарий без отдельной облачной базы.
