# «Династия»: версия для Vercel + Supabase

Пакет предназначен для обновления существующего проекта
`dom-pmr-site.vercel.app`. В нём работают публичный каталог, карта, страницы
объектов, заявки собственников, загрузка фотографий и защищённая админ-панель.

Разрешённые сотрудники:

- `polupoker@gmail.com`
- `troshinskayaa@gmail.com`

## Что понадобится

- доступ коллеги к существующему проекту Vercel;
- бесплатный проект Supabase;
- Node.js 22 или новее для локальной проверки.

Секретные значения нельзя отправлять в мессенджеры или добавлять в файлы
проекта. Они вносятся только в настройки Vercel.

## 1. Создать и настроить Supabase

1. Создать проект на `https://database.new`.
2. Открыть **SQL Editor**, создать новый запрос.
3. Скопировать весь файл `supabase/setup.sql` и нажать **Run**.
4. Открыть **Authentication → Users** и создать двух пользователей:
   `polupoker@gmail.com` и `troshinskayaa@gmail.com`.
5. Для каждого пользователя задать отдельный временный пароль не короче
   12 символов и включить подтверждение email при создании пользователя.
6. В **Authentication → Providers → Email** отключить открытую регистрацию,
   чтобы посторонние посетители не могли создавать аккаунты.

SQL создаёт таблицы, индексы, защиту RLS и публичный Storage-bucket
`property-images`. Запись в базу и загрузка файлов доступны только серверной
части сайта.

## 2. Получить три значения Supabase

В настройках Supabase скопировать:

- Project URL;
- Publishable key (`sb_publishable_...`);
- Secret service-role key.

Service-role key является секретом. Его нельзя помещать в переменную с
префиксом `NEXT_PUBLIC_`.

## 3. Обновить существующий проект Vercel

Распаковать архив и заменить исходники проекта содержимым этой папки. Если
проект связан с GitHub/GitLab, удобнее заменить файлы в подключённом
репозитории и отправить изменения в production-ветку.

Для загрузки через Vercel CLI из корня распакованной папки:

```bash
npm ci
npx vercel link
npx vercel --prod
```

При `vercel link` выбрать существующий проект `dom-pmr-site`, а не создавать
новый.

## 4. Добавить переменные в Vercel

Открыть **Project → Settings → Environment Variables** и добавить для
Production и Preview:

```text
NEXT_PUBLIC_SUPABASE_URL=<Project URL>
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<Publishable key>
SUPABASE_SERVICE_ROLE_KEY=<Secret service-role key>
```

Названия должны совпадать посимвольно. После добавления переменных обязательно
запустить новый deployment: старые публикации не получают новые значения
автоматически.

## 5. Проверить админ-панель

1. Открыть `https://dom-pmr-site.vercel.app/admin`.
2. Войти одним из созданных email и соответствующим паролем.
3. Открыть пункт **Сменить пароль** и заменить выданный пароль на личный.
4. Создать объект сначала в статусе **Черновик**.
5. Загрузить 2–3 фотографии.
6. Перевести объект в статус **Опубликован**.
7. Убедиться, что объект появился в каталоге и открывается на отдельной странице.
8. Проверить архивирование и восстановление.
9. Отправить тестовую заявку с главной страницы и проверить её в админке.

## Безопасность

- Service-role key используется только в серверных маршрутах и Vercel Variables.
- Таблицы закрыты RLS от прямого анонимного чтения и записи.
- API повторно проверяет авторизованного пользователя и список разрешённых email.
- Открытая регистрация сотрудников не предусмотрена.
- Перед передачей проекта третьим лицам временные пароли следует заменить.

## Локальная проверка

Скопировать `.env.example` в `.env.local`, подставить тестовые значения и выполнить:

```bash
npm ci
npm run dev
```

Production-сборка:

```bash
npm run build
```

Инструкции основаны на актуальных рекомендациях Supabase по `@supabase/ssr`,
парольной авторизации, Storage/RLS и документации Vercel по Next.js и
переменным окружения.
